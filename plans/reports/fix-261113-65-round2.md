## Finding 2 — press/click while locked with no attached session answers `not_attached` instead of `screen_locked`

### Root cause

`Commands.run()` after a successful `lock.resume()` called `self._slot(cmd)` for every typed op before issuing the `screen_locked` refusal. `press` and `click` have no session-attachment requirement (they target the UI layer, not a session), so `_slot` raised `not_attached` before the refusal was reached.

### Test (red on f782f23)

`tests/test_drive_screen_lock.py::test_press_or_click_while_locked_with_no_session_answers_screen_locked`

```
press: expected screen_locked, got 'not_attached'
AssertionError: 'not_attached' == 'screen_locked'
```

Red: 1 failed, 0 passed.

### Fix — `tsb_tui/drive/commands.py` `Commands.run()` (~line 364)

Added a branch before the slot lookup: for `press` and `click`, raise `screen_locked` directly without calling `_slot`. `type` and `keys` keep the existing slot-based refusal path.

```python
if typed:
    if op in ("press", "click"):
        # press and click are UI-layer sends with no session attachment requirement:
        # refuse screen_locked directly without a slot lookup (D65-R2 finding 2).
        raise DriveError("screen_locked", locked_why + "; look again before sending",
                         sent=False, locked=True)
    slot = self._slot(cmd)
    self._refuse(slot, "screen_locked", locked_why + "; look again before sending")
```

## Finding 3 — `look: "last"` after unlock resolves to the voided look and is refused `screen_locked`

### Root cause

`_check_gate` resolved `"last"` as:
```python
ident = self._last_look.get(slot.session_id) or self.d.screen_lock.void_last.get(slot.session_id)
```
After unlock, `_last_look` is empty (cleared when the lock engaged). The `or` fell through to `void_last`, which still held the pre-lock look ID. `_void_look()` then correctly identified it as voided and raised `screen_locked` with the stale idle reason — even though the drive was no longer locked.

### Test (red on f782f23)

`tests/test_drive_screen_lock.py::test_last_look_after_unlock_resolves_to_no_look_not_void`

```
expected no_look, got 'screen_locked': sender idle for 11 seconds; screen-lock time is 10 seconds
```

Red: 1 failed, 0 passed.

### Fix — `tsb_tui/drive/commands.py` `Commands._check_gate()` (~line 1121)

Fall back to `void_last` only while the lock is active.

```python
ident = cmd.get("look")
if ident == "last":
    ident = self._last_look.get(slot.session_id)
    if ident is None and self.d.screen_lock.locked:
        ident = self.d.screen_lock.void_last.get(slot.session_id)
```

After unlock with an empty `_last_look`, `"last"` now resolves to `None`, which proceeds to the ordinary `no_look` path.

## Finding 4 — `op_login` reads the password file before the "already logged in" check

### Root cause

`op_login` called `await asyncio.to_thread(read_password_file, path)` unconditionally, before checking whether drive was already logged in and not locked. A FIFO with no writer would block `open()` in that thread, stalling the entire command loop.

### Test (red on f782f23)

`tests/test_drive_screen_lock.py::test_login_already_logged_in_and_not_locked_refuses_before_reading_file`

```
AssertionError: read_password_file was called before the already-logged-in check
assert ['<the test's temporary password file>'] == []
```

Red: 1 failed, 0 passed.

### Fix — `tsb_tui/drive/commands.py` `Commands.op_login()` (~line 450)

Added an early check before the file read: if logged in and not locked, refuse immediately.

```python
if self.d.screen() is not None and not self.d.screen_lock.check():
    raise DriveError("bad_request",
                     f"already logged in as {self.d.app.username}; one driver is one login")
password = await asyncio.to_thread(read_password_file, path)
```

The locked sign-out-then-login path (`screen() is not None and screen_lock.check()`) still reads the file, as it must proceed with the new login.
