# Issue #21 — a session's end must not close the operator's unrelated dialog

**AI-Model:** strata
**Branch:** fix/tui-21-end-keeps-dialogs (base tsb-tui main `7e3dd5f`)
**Date:** 2026-11-09 (Asia/Saigon)

## What changed

The orchestrator ruled option 1 (2026-11-09 01:56). Implemented in `tsb_tui/screens/terminal.py` only,
plus tests in `tests/test_ended_and_reattach.py`. No other file touched; the ledgers and `program/` were
not.

A dialog opened for the session in front is recorded against that session's id, so a session's end pops
only its own dialogs and leaves the operator's unrelated ones open.

1. **Recording map** — `self._dialog_session: dict[screen → session_id]` (terminal.py:390) and the deferred
   slot `self._deferred_end_slot` (terminal.py:393), both in `__init__`.
2. **Push helper** `_push_session_dialog(screen, callback)` (terminal.py:2180): pushes the dialog and records
   `screen → self._front.session_id`. The six push sites that open a dialog for the front session now call it:
   ConfirmEndScreen (terminal.py:1365), ConfirmKillScreen (terminal.py:2117), WhosHereScreen
   (terminal.py:2694), SizeDialog (terminal.py:2697), AnswerScreen (the stale/quiet answer, terminal.py:2708),
   EventLogScreen (terminal.py:2779). Unrelated dialogs (New-session, credentials, login, map/save-login,
   settings/about/all-keys, theme picker, devices, search) keep pushing directly and are never recorded.
3. **End handling** `_show_end_dialog` (terminal.py:2143): prune the map, pop only the screens recorded for the
   ended slot's id (`_pop_session_dialogs`, terminal.py:2165), say the end in the status row at once
   (`refresh_status`), and if an unrecorded dialog is still open defer the ended screen
   (`self._deferred_end_slot = slot`); otherwise show it now (`_show_ended_screen`, terminal.py:2159).
4. **Deferral** `on_screen_resume` (terminal.py:2187): when the last modal over the workspace closes, show the
   deferred ended screen only if the ended session is still the front one, not closed, and its dialog not shown.
5. **Prune** `_prune_dialog_sessions` (terminal.py:2173): drop recorded screens no longer on the stack.

The end words in the status row at once need no status-row change: `_ended_status`/`_special`
(status_row.py:327) already render `✕ ended · …` ahead of a dialog's keys line whenever the front session has
ended, so `refresh_status()` after the pop shows it whether a dialog is open.

The ruling's step 1 was the blocker in the prior report (no screen recorded its session). Option 1 creates that
record inside terminal.py; the deferral rides on Textual's `on_screen_resume`, which fires when the last modal
closes. No design decision was left to choose — the ruling specified the mechanism in full.

Tests 2 and 3 **passed before the fix**: they encode as-today behaviour (the session's own dialog popped, ended
screen at once; no-dialog case unchanged), which the ruling explicitly preserves. They are regression guards,
not red-first. I report this plainly rather than force a false red.

## Decisions left open (none for this change)

The ruling settled the mechanism. Two behaviours it did not enumerate remain as the ruling's, not mine:
- A session dialog buried **under** an unrelated dialog cannot be popped without touching the unrelated one
  (`pop_screen` pops the top). `_pop_session_dialogs` stops at the unrelated top and defers; when that dialog
  closes, `on_screen_resume` pops the session's own dialogs then shows the ended screen. This is the only
  reading consistent with "leave every other screen untouched"; no test covers the buried case, so it is not
  proven by a new test.
- ConfirmEndScreen opened from a fleet-view row for a non-front session records the **front** slot's id, as the
  ruling's step 1 says ("record against the front slot's session id"). A confirm-end for a non-front session is
  not popped at that session's end; no test covers it.
