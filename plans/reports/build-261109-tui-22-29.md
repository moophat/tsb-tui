## Fix 1 — close the handed-over device-login socket when the slot dies before its pump starts

The ruling: a slot released before its pump started (`adopt_device_attachment`, then `_close_slot`
cancelling the attach worker before `_attach_and_pump` runs) must close the device-login attachment
itself, and close the never-started coroutine so no "coroutine was never awaited" RuntimeWarning is
left.

`tsb_tui/screens/terminal.py`:
- `SessionSlot` gains `device_attachment` and `attach_coro` (terminal.py:318-319): the socket the
  device login handed over, and the pump's coroutine before its worker ever ran.
- `adopt_device_attachment` (terminal.py:1500-1502) stores both on the slot before starting the worker.
- `_release_slot` (terminal.py:2278-2286): when `slot.pump is None` the worker never ran its body, so
  nothing owns the socket; close the coroutine (`attach_coro.close()`) and spawn
  `device_attachment.close()`. When the pump started, the pump owns the socket and its `finally`
  closes it as before — the close never races a live pump.

Test: `tests/test_attach_and_close.py::test_a_slot_closed_before_its_pump_started_closes_the_handed_over_device_login_socket`
(tests/test_attach_and_close.py:208). A device login answered to the end hands its socket over; the slot
is adopted and closed in the same loop iteration (the worker's task never steps); warnings are captured
(`warnings.catch_warnings(record=True)`), then `del slot; gc.collect()`. Asserts the attachment's socket
is closed and no RuntimeWarning naming a coroutine was recorded.

Red-first evidence (run once before the fix, same command as below):

```
E  AssertionError: the slot closed and left the handed-over socket open
E  assert False
1 failed in 1.75s
```

A direct probe of the same flow on the unfixed code also showed the warning the test's warnings capture
catches: `never-awaited warnings: ["coroutine 'TerminalScreen._attach_and_pump' was never awaited"]`
with `socket closed: False`.

## Fix 2 — the half-login assertion counts only what a half login can cause

`tests/test_new_session_login.py`:
- New helper `_half_login_calls` (tests/test_new_session_login.py:49-56): counts only the requests a
  half login can cause — `POST /sessions` and the target read (`GET /targets`, `GET /targets/{id}`),
  as `(method, path)` pairs. The fleet poll, the activity signal and any other request on the app's own
  timers are not counted, so they can no longer fall inside the window.
- `test_half_a_login_is_refused_before_any_call` (tests/test_new_session_login.py:185-193): baseline and
  assertion use `_half_login_calls`; the failure message prints the leaked `(method, path)` pairs, so a
  failure names which request leaked.

Red-first evidence: run once against a deliberately broken copy of the create path — `NewSessionScreen._half_login`
made to return `False`, so a half login sends the create. The test failed:

```
E  textual.css.query.NoMatches: No nodes match '#new-session-error' on NewSessionScreen()
1 failed in 1.76s
```

The dialog left the screen because the create succeeded (the attach gate was pushed) — the half login
reached the core, and the test caught it. The break was reverted (`git status` clean for
`tsb_tui/screens/new_session.py`).
