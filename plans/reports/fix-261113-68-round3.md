## Finding

**Source:** Qodo review on fb07260.

**Location:** `tests/test_credentials_screen.py` — `test_a_refresh_press_while_a_load_is_running_is_not_overwritten_by_the_stale_load`, the release-then-assert tail.

**Description:** The refresh-race test releases the blocked first request (`block.set()`) and then
waits a fixed 0.5 s (`await pilot.pause(0.5)`) before asserting the newest label stays. A fixed pause
is not bound to any condition: under CI load the stale first load's worker may not have finished and
its callback may not have run by the time the assertion fires, so the test can assert on the screen
before the stale answer lands and pass even when the bug is present.

## Fix

**File:** `tests/test_credentials_screen.py`

**Change:** After `block.set()`, replaced the fixed `await pilot.pause(0.5)` with a bounded
condition wait for the released first load's worker to finish and its callback to run on the UI
thread, reusing the `_run_blocking` worker-finish pattern already in this file (the torn-down-table
test, `test_a_load_answer_after_the_table_is_gone_is_dropped_without_an_exception`). The assertion
follows that wait unchanged.

```
block.set()
# Wait, bounded, for the released first load's worker to finish and its callback to run on the UI thread
# (the same `_run_blocking` pattern as the torn-down-table test): a fixed pause can assert before the stale
# answer lands under CI load and pass even when the bug is present.
await wait_until(pilot, lambda: not any(w.name == "_run_blocking" and not w.is_finished
                                        for w in app.workers), "the first load's worker to finish", 30.0)
assert "core switches" in screen_text(app), \
    "the newest refresh's label must survive a stale load that finishes after it"
```

`call_api` runs `func` in the `_run_blocking` thread worker and, when it returns, posts `on_done`
back to the UI thread with `call_from_thread`. The predicate becomes true only once that worker is
finished; `wait_until` drives the app's event loop on each tick, so the posted callback (the stale
load's `_listed`, dropped by the generation guard) runs on the UI thread before the assertion. The
timeout (30.0 s) matches the surrounding waits in this test and the reused pattern.

The fix touches only the test; no production code changed. The orchestrator proves the test still
catches the bug on the pre-fix code; per the brief that was not re-run here.
