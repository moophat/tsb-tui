## Ruling and Changes

Qodo flagged that `test_macos_readme_commands` was checked in no CI job.
The orchestrator re-ruled the finding to Qodo's option (a): `test_macos_readme_commands`
builds from cached inputs and skips when they are absent, so adding it to the release container
step would most likely skip and pass silently.

Instead:
1. Reverted the `release.yml` change and its accompanying test in `test_release_install.py`.
2. Updated staged-zip verification (`test_staged_macos_zips` and `check_zip`) to read `README.txt`
   and assert both command lines:
   - `'Run: ./tsb-tui --broker https://<host>'`
   - `'Check the engine and TUI versions: ./tsb-tui-check'`
   Since the release workflow already runs `test_staged_macos_zips` on all staged zips before publish,
   the README commands are enforced on release artifacts without skipping.
3. Added `test_staged_macos_zip_missing_readme_commands_fails` in `packaging/tests/test_macos_build.py`.
   It constructs a minimal staged zip in `tmp_path` and asserts that missing either or both commands
   triggers an `AssertionError`, whereas providing both lines passes and proceeds to `check_zip`.
   The new test requires no cached inputs and runs in PR CI.
